# M5：来源验证、确认防重放与记忆生命周期

M5 把社区反馈中的三个安全不变量落到账本核心：候选晋升前必须重新验证来源，用户确认凭证必须绑定当前候选版本并可安全重试，长期记忆只能沿着明确的生命周期状态转换。

## 来源验证

`promote()` 会重新读取每条 EvidenceRef，并验证：

- workspace、session ID 和事件序号仍指向同一个事件；
- 事件内容哈希未变化；
- 事件时间未变化（两端都提供时）；
- `sourceGeneration` 未变化（候选记录了来源版本时）；
- 来源仍可读取且仍属于当前 workspace。

来源不存在、授权改变或来源版本变化都会拒绝晋升，并返回可区分的错误码。

## 确认防重放

每次 `issueConfirmation()` 都生成新的 confirmation ID，并把它绑定到候选内容哈希、证据哈希、workspace 和过期时间。重新签发会使之前的 token 失效。

晋升在进程内按 candidate ID 串行化。成功写入后，候选记录保存 `consumedAt`；重试已完成的晋升只返回同一条记忆，不会产生重复记录。若在写入过程中恢复到 `confirmed` 状态，只接受原 confirmation token 继续补偿。

## 生命周期状态机

候选过期会持久化为终态 `expired`。记忆状态使用统一转换约束：

```text
ACTIVE -> REVOKED -> DELETED
   \----------------> DELETED
```

删除会清空正文和证据，但保留必要的审计元数据；已删除记忆不能再次撤销。
